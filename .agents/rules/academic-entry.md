# Academic Task Entry

本规则用于连接项目约束与通用学术写作技能。

## 任务开始

处理本项目学术文本之前：

1. 先读取 `PROJECT_NOW.md`，确认当前任务与有效状态。
2. 读取 `docs/PROJECT_FACTS.md`，确定当前有效的项目事实。
3. 读取 `docs/TERMINOLOGY.md`，确定术语和表达偏好。
4. 根据任务读取适用的章节契约（存放在 `docs/contracts/`）作为章节功能与结构参考，结合实际证据组织内容。注意契约中的未决技术路线与任务细分不得直接升级为已确定的研究决定。
5. 使用 `academic-writing` 执行内容构思、起草或审校。

不得将 `PROJECT_STATUS.md` 中的历史叙述直接当作当前决策。

不得读取或恢复 `AGENTS.md` 已明确隔离的作废资料。

## 信息状态与事实分级

处理文本时须严格区分四类信息状态，严禁混淆：

- **CONFIRMED**：已由项目负责人确认，或由可核实原始证据支持的有效事实或决定。
- **PROVISIONAL**：暂定方案或工作假设，可作为讨论与前期推演基础，但尚未最终锁定。
- **UNDECIDED**：仍待后续研究、算法比选或等待用户确认的事项。
- **HISTORICAL**：历史演进记录或曾经的探索足迹，不自动具有当前约束效力。

## 事实与规则冲突

发现来源之间存在冲突时：

- 优先识别当前有效且已确认的事实（CONFIRMED）。
- 区分用户确认、原始证据与历史记录。
- 无法消除的冲突必须明确报告。
- 不得通过推测、混合表述或多数来源投票解决事实冲突。

## 写作与交付

- 起草前进行事实和证据核对。
- 起草时按照 `academic-writing` 的通用质量标准组织论证。
- 完成后核对项目事实、术语及证据。
- 有自动检查脚本时必须实际执行。
- 检查未执行或失败时，不得声称已经通过验收。
- 未获授权，不修改本次任务范围之外的正式文件。

研究路线及阶段决策由项目专属文件管理，不由本规则或通用写作技能决定。
