## 二、 核心理论深挖一：为什么推力分配会如此“尴尬”？

在传统分层控制架构中，推力分配是作为“控制器与执行器之间的翻译官”存在的：

```text
【传统分层架构的割裂】
 上层控制器 (PID/滑模) ──► 算6维总力矩 τ (不管电机能不能做到)
                                │
                                ▼
 下层控制分配器 (Allocation) ─► 解 τ = B * f 映射到8个推进器
                                (电机饱和时被迫削减推力，导致力矩畸变，反噬上层控制)
```

推力分配之尴尬，本质在于两点：
1. **学术上毫无创新空间**：无约束下求 Moore-Penrose 伪逆 $\mathbf{f} = \mathbf{B}^\dagger \boldsymbol{\tau}$ 只是微秒级的矩阵乘法；有约束下解一个小规模 QP 也是十几年前的标准做法。将其作为毕业论文的核心理论攻坚，会被内行一眼看穿为“强行注水”；
2. **现代先进算法中早已被整合吸收**：先进的现代 MPC 可以直接在优化问题内部完成单推进器推力求解与物理饱和处理，独立的推力分配模块在理论上被完全“吞并”。

## 三、 核心理论深挖二：ROV 领域 MPC 算到哪一步？

通过对 IEEE T-RO、Ocean Engineering 等顶级文献与开源生态的系统调研，ROV 领域的 MPC 存在两大发展流派：

| 维度 | 流派一：分层式 MPC (Hierarchical MPC) | 流派二：一体化 MPC (Integrated / Direct MPC) |
| :--- | :--- | :--- |
| **控制决策变量** | 6 维总广义力/力矩 $\mathbf{u} = \boldsymbol{\tau} \in \mathbb{R}^6$ | 8 个单推进器推力 $\mathbf{u} = \mathbf{f} \in \mathbb{R}^8$ |
| **系统模型形式** | $\mathbf{M}\dot{\boldsymbol{\nu}} + \mathbf{C}\boldsymbol{\nu} + \mathbf{D}\boldsymbol{\nu} + \mathbf{g} = \boldsymbol{\tau}$ | $\mathbf{M}\dot{\boldsymbol{\nu}} + \mathbf{C}\boldsymbol{\nu} + \mathbf{D}\boldsymbol{\nu} + \mathbf{g} = \mathbf{B}\mathbf{f}$ |
| **推力饱和处理** | MPC 只能约束宏观合力，无法预知具体电机极限；下层分配器被动截断/缩放 | **单电机推力幅值与变化率直接作为 MPC 的硬约束/软约束** |
| **独立分配器** | **必须有**（伪逆或局部 QP 分配） | **完全不需要**（推力分配被优化器隐式完成） |
| **力矩保形机制** | 需人工设计复杂的“力矩优先保形截断法则” | **数学优化天然保形**（优化器权衡后自动牺牲平移以保姿态） |
| **典型应用场景** | 早期低算力平台、或直接挂接 PX4/ArduSub 现成接口 | 现代顶刊研究、学长提到的 Full-DOF MPCC 敏捷控制 |

> **关键洞察**：学长指出“MPC 可以直接算到单推力”，指的正是**流派二（一体化 MPC）**。这也是为什么学长认为推力分配在理论上没有独立存在的必要。

## 四、 核心概念通俗化：什么是 MPC？模型在其中起什么作用？

### 1. 通俗比喻：PID 是“盲人拄拐”，MPC 是“推演未来的老司机”
* **经典 PID**：完全被动挨打。它不知道航行器有多重、不知道水阻有多大，只看当前位置偏了没有。偏了就反推，结果因为水下巨大惯性刹不住车，产生超调振荡；
* **MPC（模型预测控制）**：在每一个控制周期（例如每隔 50ms），老司机抬头看未来的目标轨迹，在脑海中利用物理模型做**未来推演**：
  1. **预测未来（Prediction）**：推演在未来 $1\sim 2$ 秒内，如果给推进器施加某种推力序列，航行器会走出怎样的空间轨迹；
  2. **滚动优化（Optimization）**：在成千上万种推力组合中，选出一组“既咬合轨迹、又最省电、且任何电机都不超载”的最优推力；
  3. **只走一步，重新推演（Receding Horizon）**：只执行前 50ms 的推力，随后拿到最新传感器数据，重新向后预测 1 秒。

### 2. 模型（M）的作用：预知未来的物理“水晶球”
MPC 预测未来的能力完全依赖于其内部的物理模型 $\mathbf{M}$：
* **水动力非线性阻尼模型**：告诉 MPC 速度加快时水阻将按平方剧增，必须提前加大出力；
* **附加质量（Added Mass）模型**：告诉 MPC 航行器推开周围水体时的真实有效惯性，刹车必须提前打反推；
* **推进器安装矩阵 $\mathbf{B}$**：告诉 MPC 8 个推进器的空间力矩臂与合成规律。
* **逻辑闭环**：**没有精确的系统辨识，MPC 的“M”就是瞎子；有了学长手里的高精度辨识算法，MPC 才能如虎添翼！这正是“模型是 Base”的真谛所在。**

### 3. 频率现实：为什么水下 MPC 跑在 10Hz~20Hz 完全够用？
* **四旋翼无人机**：空气中惯性极小、动态极快，内环必须跑在 **200Hz ~ 1000Hz**，否则瞬间炸机；
* **水下航行器**：水的密度是空气的 800 倍，附加质量和黏性水阻极大，物理动态极其迟缓（时间常数达 $0.5\sim 2$ 秒量级）。
* **黄金分工**：
  * **上位机（Jetson Orin 跑 MPC）**：跑在 **10Hz ~ 20Hz（50ms ~ 100ms 一次）**，单次优化求解耗时仅 2~5ms，算力与实时性绰绰有余；
  * **底层飞控（Pixhawk 6C 跑内环与 PWM）**：跑在 **50Hz ~ 100Hz**，负责高频传感器滤波和平滑驱动输出。

## 八、 2026-10-09 最新交流共识深化：轨迹跟踪具体任务与辨识方法体系收敛

> **交流时间**：2026-10-09 09:00 ~ 10:17  
> **核心突破**：将宏观控制路线具体化为**“基于辨识模型的预测控制与全自由度姿态可变轨迹跟踪”**，收敛辨识模型为四大流派（Fossen、Neural ODE、Port-Hamiltonian、SINDy），并明晰了“机载预测控制 + 板载姿态 PID”的分层部署架构。详见专题记录文件：[20261009_学长最新交流共识_轨迹跟踪任务与辨识模型体系.md](20261009_学长最新交流共识_轨迹跟踪任务与辨识模型体系.md)。

### 1. 核心任务锁定：全自由度姿态时变轨迹跟踪（Trajectory Tracking）
* **学长原话**：“轨迹追踪 / trajectory tracking”；“基于辨识模型的预测控制与轨迹跟踪 这个吧 更像是一个具体的任务”；“姿态也要变 但会难一点 对具体姿态有要求”。
* **技术内涵**：
  * 控制目标绝非单纯的定深定高或静止悬停，而是**复杂空间几何曲线与动态时变位姿的协同跟踪**；
  * 八推进器矢量紧凑型航行器具备全自由度主动调姿能力，轨迹跟踪要求航向角 $\psi(t)$、俯仰角 $\theta(t)$ 及横滚角 $\phi(t)$ 随作业要求动态调整，形成高维、非线性、强耦合的多轴跟踪控制问题。

### 2. 系统辨识本质与四大方法体系
* **学长原话**：“辨识就是一个模型，可以是参数化模型，也可以是非参数化模型。看作一个黑盒的话，输入就是状态和控制量，输出就是系统动态”；“基于Fossen的方法；也有Neural ODE的方法；也有有能量约束的Port-Hamiltonian的方法；还有SINDy（附 Brunton 2016 论文）”。
* **体系收敛**：
  1. **基于 Fossen 的机理/灰盒参数辨识**：水动力参数动量回归（Park 2016）与加权最小二乘法；
  2. **Neural ODE（神经常微分方程）**：连续时间动态网络拟合（Chen 2018/2019）；
  3. **有能量约束的 Port-Hamiltonian 神经网络（PHS / PH-NODE）**：具备能量守恒与无源性约束的物理增强学习（Duong 2024）；
  4. **SINDy（稀疏非线性动力学辨识）**：基于候选基函数字典与稀疏回归的数据驱动显式方程发现（Brunton 2016）。

### 3. 控制系统架构与软硬件分工
* **学长原话**：“姿态控制是pid”；“到时候看情况吧，可能所有都自己控，但姿态我觉得还是放板子上好一点”。
* **部署策略**：
  * **主推分层分级架构**：机载计算机（上位机）以 10Hz~20Hz 运行高规格 MPC 预测控制算法（基于辨识模型滚动优化轨迹与期望加速度/姿态），飞控板（PX4 MCU）以 50Hz~100Hz 运行底层姿态内环 PID 与推力分配，兼顾算法复杂度与高频闭环稳定性；
  * **兼顾一体化自控备选**：机载端统一直接解算单推力下发，开题报告保持方案开放性与比选弹性。
